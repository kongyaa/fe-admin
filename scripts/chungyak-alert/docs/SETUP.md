이 저장소는 공개 저장소입니다. 키, 받는 메일, Notion ID는 파일에 쓰지 말고 GitHub Secrets에만 넣으세요.

1. 회원 가입 후 다음 6개 API를 활용신청합니다.
   - 청약홈 분양정보 조회 서비스 (15098547)
   - 국토교통부 아파트 매매 실거래가 상세 또는 해당 자료 (15126469)
   - 국토교통부 아파트 분양권전매 실거래가 자료 (15126471). 승인 전에도 배치는 돌아갑니다. 오류 메일 없이 시세 신뢰도가 한 단계 낮아지고 로그에 `presale_` 건수만 남습니다.
   - 국토교통부 공동주택 단지 목록제공 서비스 (15057332)
   - 국토교통부 공동주택 기본 정보제공 서비스 (15058453). 이 둘은 승인 전에도 배치가 돌아갑니다. 비교 단지의 역 보정이 빠지고 신뢰도가 낮아지며 오류 메일 없이 로그에 건수만 남습니다.
   - LH 임대공고 조회
2. 마이페이지에서 일반 인증키를 복사해 `DATA_GO_KR_KEY`로 등록합니다. 디코딩 키를 권장합니다. 인코딩 키를 넣어도 코드가 풀어서 씁니다.

## 2. Notion

1. https://www.notion.so/my-integrations 에서 이 배치에 쓸 내부 통합의 토큰을 `CHUNGYAK_NOTION_KEY`로 등록합니다. 저장소의 기존 `NOTION_KEY` Secret은 다른 통합의 것이므로 쓰지 않습니다. 워크플로가 이 값을 환경 변수 `NOTION_KEY`로 넘깁니다.
2. 대상 페이지의 연결 메뉴에서 그 통합을 추가합니다.
3. 페이지 URL 끝의 32자리 ID를 `CHUNGYAK_NOTION_PAGE_ID`로 등록합니다.

첫 실행 때 데이터베이스, 소스 목록 페이지가 자동 생성되고, 첫 주간 메일 뒤 "청약 배치 상태" 페이지가 생깁니다. 이 페이지 제목의 날짜가 주간 메일 중복을 막으니 지우거나 고치지 마세요.

카카오맵 사용 설정은 필요 없습니다. 이 배치는 카카오 지도와 로컬 API를 쓰지 않으므로 켜 두었다면 꺼도 됩니다. 메시지 발송과 토큰 갱신에는 영향이 없습니다.

1. 앱의 REST API 키를 `KAKAO_REST_KEY`로 등록합니다.
2. 클라이언트 시크릿을 켰다면 값을 `KAKAO_CLIENT_SECRET`으로 등록합니다. 쓰지 않으면 비워 둡니다.
3. PC에서 최초 인증을 1회 실행합니다.

   ```powershell
   cd scripts/chungyak-alert
   $env:KAKAO_REST_KEY = "REST 키"
   $env:KAKAO_CLIENT_SECRET = "시크릿, 없으면 이 줄 생략"

   ```

4. 출력된 주소를 열어 동의하면 `.kakao-token.txt`가 생깁니다. 내용을 `KAKAO_REFRESH_TOKEN`으로 등록한 뒤 파일을 지웁니다. 이 파일은 커밋되지 않도록 제외되어 있습니다. 동의 화면에서 메시지 전송 항목을 꼭 선택하세요. 선택 동의라 해제하면 발송이 실패합니다.

## 5. Secret 쓰기용 PAT

카카오 갱신 토큰이 교체되면 워크플로가 Secret을 직접 갱신합니다.

1. GitHub Settings > Developer settings > Fine-grained personal access tokens에서 새 토큰을 만듭니다.
2. Repository access는 **이 저장소만** 선택합니다.
3. Repository permissions에서 **Secrets: Read and write**만 줍니다.
4. 값을 `KAKAO_SECRET_WRITER_PAT`으로 등록합니다.
5. **토큰은 만료됩니다.** 만료일을 정하고 그 전에 갱신하도록 달력에 적어 두세요. 만료되어도 평소에는 문제가 드러나지 않다가 갱신 토큰이 교체되는 날 실패합니다.

## 7. 확인 순서

Actions 탭에서 `chungyak-alert`를 수동 실행합니다.

1. `dry-run`: 수집과 판별만 합니다. Notion은 관심 후보를 세려고 읽기만 합니다. 로그에서 건수와 오류 유형을 봅니다.
2. `test-send`: 표시된 샘플 메일 1통과 카카오 1건을 보냅니다. Notion에는 쓰지 않습니다.
3. `normal`: Notion 저장을 확인합니다. 두 번 실행해 중복 행이 없는지 봅니다.
4. `force-weekly`: 주간 메일을 강제 발송합니다.

### 접수가 끝난 페이지 정리

저장된 접수 종료일이 오늘(KST) 이전인 페이지는 두 경로로 Notion 휴지통으로 옮겨집니다. 영구 삭제가 아니라 휴지통 이동이며, 접수 종료일이 오늘 이후이거나 비어 있는 페이지는 그대로 둡니다.

**주간 메일 발송 때 자동 정리**

- 주간 메일 발송과 발송 기록이 모두 성공한 실행에서만, 긴급 알림까지 끝낸 뒤 정리합니다. `force-weekly`도 포함합니다.
- 메일이 실패하거나 미뤄진 실행, 그 주의 다른 실행, `dry-run`, `test-send`에서는 정리하지 않습니다.
- 일부가 실패하면 오류 메일에 `cleanup_failed`로 표시되고 잡이 실패합니다. 이미 보낸 메일은 그대로이며, 남은 페이지는 다음 주 발송 때 다시 정리됩니다.
- 로그의 `archived`가 옮긴 건수입니다.
- 휴지통으로 옮긴 공고가 정정되어 접수가 다시 열리면 다음 실행에서 새 페이지로 저장됩니다.

**수동 정리 `cleanup-ended`**

수동 실행 전용입니다. 예약 실행에서는 돌지 않습니다.

- 수집, 저장, 메일, 카카오 발송을 하지 않고 카카오 토큰도 갱신하지 않습니다.
- 로그에는 `archived`, `kept`, `failed` 건수만 남고, 하나라도 실패하면 잡이 실패합니다. 메일로는 알리지 않으니 Actions 결과를 확인하세요.
- 잘못 옮겼다면 Notion 휴지통에서 복원할 수 있습니다. 휴지통 보관 기간은 Notion 정책을 따르므로 필요하면 바로 확인하세요.
- PC에서 대상 건수만 보려면 `NOTION_KEY`와 `CHUNGYAK_NOTION_PAGE_ID`를 설정하고 `node src/main.js --cleanup-ended --dry-run`을 실행합니다.

PC에서 조회만 하려면 다음과 같이 실행합니다. `--print`는 쓰기와 발송을 하지 않으며 Actions에서는 무시됩니다.

```powershell
$env:DATA_GO_KR_KEY = "키"
npm run dry-run
node src/main.js --print
```

## 8. 운영 주의

- **60일 규칙:** 공개 저장소의 예약 워크플로는 저장소 활동이 60일 없으면 자동으로 꺼집니다. 꺼지면 Actions 탭에서 `chungyak-alert`를 선택해 **Enable workflow**를 누르세요. 기존 일일 리포트 커밋을 멈추면 이 일이 생길 수 있습니다.
- **카카오 토큰 복구:** `kakao_secret_write_failed` 메일을 받으면 새 갱신 토큰이 저장되지 않은 상태입니다. PAT를 고친 뒤 3장의 최초 인증을 다시 하고 Secret을 등록하세요.
- **갱신 토큰:** 워크플로가 매일 갱신을 실행하므로 알림이 없어도 쓰지 않아 만료되는 일은 없습니다. 카카오 쪽 동의 철회나 비밀번호 변경 등으로 끊기면 `kakao_access_token_missing` 메일이 옵니다.
- **Notion 오류:** Notion을 읽지 못해도 긴급 알림은 보냅니다. 발송 기록을 남기지 못하므로 같은 날 다음 실행에서 또 올 수 있고, 오류 메일에 `urgent_sent_without_stamp`로 표시됩니다. 주간 메일은 발송 기록이 필요해 Notion이 복구된 뒤 보냅니다. 잡은 실패로 끝납니다. 실행 중 Notion이 응답하지 않으면(`notion_timeout`, `notion_network`) 그 실행에서는 Notion 호출을 멈추고 같은 방식으로 처리합니다. 이때 저장하지 못한 공고는 접수가 끝나기 전이면 다음 실행에서 저장됩니다.
- **저장 범위:** 접수가 이미 끝난 공고는 Notion에 새로 넣지 않습니다. 날짜가 없는 LH 공고는 상태에 `마감`이나 `종료`가 들어 있으면 같이 건너뜁니다. 날짜도 마감 상태도 없는 공고는 저장합니다. 이미 Notion에 있는 페이지는 접수가 끝나면 주간 메일 발송 때 휴지통으로 옮겨집니다. 로그의 `skipped`는 이렇게 건너뛴 공고와 접수가 끝나 갱신하지 않은 기존 페이지를 합친 수입니다.
- **긴급 알림 유실:** 카카오와 메일이 모두 실패하면 오류 메일 항목 `urgent_lost`가 생기고 잡이 실패합니다. 메일까지 막혀 있으면 이 표시도 받지 못할 수 있으니 Actions 실패 알림을 켜 두세요.
- **청약홈 전체 실패:** 청약홈의 모든 조회가 실패하면 LH가 정상이어도 잡이 실패합니다.
- **관심 알림:** `관심`을 체크한 공고는 접수 시작일이 오늘(KST)이면 지역과 로또 여부와 상관없이 `[관심 청약]` 카카오톡이 갑니다. 같은 날 로또 알림과 겹치면 로또 알림 한 건만 갑니다. 마지막 실행(10:00, 지연될 수 있음) 뒤에 체크하거나 접수 시작일이 지난 공고를 체크하면 그 알림은 가지 않습니다. 접수가 끝난 공고는 체크해도 정리 대상입니다.

## 9. 로또 판별 설정

`config.json`의 `lotto.includePriceCap`(분양가상한제), `lotto.includePublicDistrict`(공공주택지구)는 기본값이 켜짐입니다. 수도권의 해당 아파트 공고는 시세와 무관하게 로또로 표시되고, 접수 시작일에 긴급 알림이 갑니다. 끄려면 값을 `false`로 바꾸세요.

`lotto.minMarginManwon`(3억 원)과 `lotto.minMarginRate`(20%)는 안전 마진과 마진율에 적용합니다. 기준값은 예전 `예상 차익`, `차익률` 기준과 같습니다. 조건형 로또는 마진이 음수여도 로또로 유지되고 판별 근거에 마진을 함께 적습니다. 가격 기준만으로 로또가 되려면 추정 신뢰도가 `중` 이상이어야 합니다. `하`이면 기준을 넘어도 `아님`이고 판별 근거 앞에 `가격 기준은 넘지만 추정 신뢰도가 하라 로또로 보지 않음`이라고 적습니다. 반대로 이미 로또로 기록된 공고가 신뢰도 `하`인 추정으로 `아님`이 되려 하면 로또를 유지하고 `이전 판별 유지(이번 추정 신뢰도 하)`라고 적습니다. 약한 추정 하나로 알림이 생기거나 사라지지 않게 하려는 것입니다. dry-run도 읽어 둔 Notion 행으로 같은 규칙을 적용합니다. 토지임대부, 지분적립형, 신혼희망타운은 `market.restrictedNameKeywords`와 신혼희망타운 유형 코드로 찾아 어떤 조건보다 먼저 `대상 외`로 두고 저장된 추정 시세, 안전 마진, 마진율, 시세 신뢰도를 지웁니다. 유형 코드도 함께 봅니다.

## 10. 안전 마진과 시세 보정

**`config.json`의 `market` 값은 모두 판단이 들어간 시작값입니다.** 실측으로 정한 값이 아니므로 정확도를 보장하지 않습니다. 결과를 보고 조정하세요. JSON에는 주석을 쓸 수 없어 여기에 적습니다.

**직접 입력할 값:** Notion의 `역 도보(분)`에 공고 단지에서 가장 가까운 지하철역까지의 도보 시간을 숫자로 넣습니다. 아직 없는 아파트라 공공 데이터에 값이 없어 카카오맵 등을 보고 직접 넣습니다. 배치는 읽기만 하고 덮어쓰지 않습니다. 없으면 역 보정 없이 계산하고 신뢰도는 `중`까지만 오릅니다. 입력이 있는 공고만 공동주택 API를 호출합니다.

계산 순서는 다음과 같습니다. 코드는 `src/market-estimate.js`입니다.

1. 취소, 직거래, 1~2층(`tradeFilter.lowFloorMax`), 토지임대부 거래를 뺍니다. 값이 없는 항목은 거르는 근거로 쓰지 않습니다.
2. 공고 단지의 거래(분양권 포함)가 `sameComplex.minSamples`건 이상이면 보정 없이 그 값을 씁니다. 신뢰도는 `상` 또는 `중`입니다. 이름은 같거나 한쪽이 다른 쪽을 포함하면 같은 단지로 보되, 브랜드를 뺀 부분이 `minDistinctiveLength`자 미만이면 포함 관계를 인정하지 않습니다. 공고 주소에 법정동이 없으면(신도시 블록 주소 등) 이름이 정확히 같을 때만 인정합니다.
3. 아니면 거래를 단지 단위로 묶습니다. 단지 안의 이상치(`outlierBand`)를 빼고 최근 거래에 가중치(`recencyHalfLifeMonths`)를 둔 단가 하나를 남깁니다.
4. 비교 단지는 연식이 공고 단지와 가까운 단지를 먼저 고릅니다. 공고 단지는 입주 전이라 0년으로 보고, `comparables.preferMaxAgeYears`(15년) 이내 단지를 같은 법정동, 같은 시군구 순으로 찾습니다. 표본이 `lotto.minSamples`, 단지 수가 `comparables.minComplexes`(2곳)에 못 미치면 `ageWidenSteps`(25년, 그다음 연식 무관)로 넓힙니다. 25년으로 넓히면 신뢰도를 한 단계 내리고, 연식 무관으로 고르면 `하`입니다. 같은 법정동에 거래가 `lotto.minSamples` 이상 있었는데 연식 때문에 시군구 단지를 고르면 위치가 다른 만큼 한 단계 더 내립니다. 단계 안에서는 표본이 많은 순으로 `maxComparables`곳까지 고릅니다. 같은 법정동에 싸고 거래가 많은 구축이 섞여 있어도 신축 비교 단지가 밀려나지 않게 하려는 것입니다. 좌표가 없어 거리는 보지 않습니다. 시군구 경계 너머의 단지는 보지 않습니다.
5. 단지 단가를 공고 단지 조건으로 환산합니다. 비율은 `공고 단지 계수 / 비교 단지 계수`이고 전체 비율은 `minFactor`~`maxFactor`로 제한합니다.
   - **역 도보(`adjustment.station`):** 5분 이내 1.06, 10분 1.04, 15분 1.02, 20분 1.00, 그 밖 0.97. 공고 단지는 직접 입력한 분, 비교 단지는 공동주택 상세 정보의 지하철역 거리를 씁니다. 값이 구간이면 윗값으로 봐서 `5~10분이내`는 10분, `20분초과`는 그 밖입니다. 구간 표는 시작값이며 실제 시세 차이를 측정한 값이 아닙니다.
   - **브랜드(`adjustment.brand`):** 상위 1.05, 중위 1.02, 그 밖 1.00. 공고 단지는 단지명 키워드, 없으면 청약홈 시공사(`CNSTRCT_ENTRPS_NM`)의 첫 회사로 봅니다. 비교 단지는 실거래 자료에 시공사가 없어 단지명으로만 봅니다. 그래서 브랜드가 이름에 없는 비교 단지는 시공사가 대형사여도 중립으로 계산되어, 같은 조건의 공고 단지보다 낮게 평가될 수 있습니다. 모르는 브랜드는 중립입니다.
   - **연식(`adjustment.age`):** 1년에 0.5%, 최대 20년(0.90). 10년 된 역세권 상위 브랜드 단지가 입주 전 무브랜드 단지보다 낮아지지 않게 잡은 값입니다. 공고 단지는 입주 전이라 신축으로 봅니다. 건축년도를 모르는 비교 단지는 보정하지 않고, 분양권 거래만 있는 단지는 신축으로 봅니다.
6. **비교 단지 역 값 찾기:** 실거래 단지명을 공동주택 목록의 단지명과 맞춥니다. 같은 법정동에서는 이름이 같거나 2번과 같은 규칙으로 포함될 때, 시군구 전체에서는 이름이 정확히 같을 때만 받습니다. 브랜드만 있는 이름은 받지 않고 후보가 여럿이면 고르지 않습니다. 못 찾은 단지는 역 계수를 받지 않습니다. 값이 있는 단지 비율이 `comparables.minStationShare`(0.6)보다 낮으면 섞지 않고 그 주택형 전체에서 역 보정을 뺍니다.
7. 보정 뒤 단지별 단가의 중위값(짝수 개면 가운데 둘의 평균)에서 `outlierLow`(0.7배) 아래나 `outlierHigh`(1.4배) 위인 단지를 뺍니다. 벗어난 단지가 고른 단지의 `outlierMaxShare`(25%)를 넘으면 시세가 둘로 갈린 것으로 보고 빼지 않으며, 빼고도 `outlierMinRemaining`(4곳) 이상 남을 때만 뺍니다. 신뢰도와 할인율은 빼기 전 전체 단지로 계산합니다. `추정 시세`는 남은 단지의 중위값입니다. 단지마다 같은 가중치입니다.
8. `안전 마진`은 `보수 시세 - 최고 분양가 - 옵션비(optionCostManwon) - 취득세`입니다. 보수 시세는 `추정 시세 × (1 - 할인율)`입니다. 비교 단지가 `safeValue.minComplexesForLoo`(4곳) 이상이면 할인율은 단지끼리 서로를 맞혀 본 오차(leave-one-out)의 중위값과 퍼짐(사분위 범위/중위값)의 절반 중 큰 값을 `minDiscount`(5%)~`maxDiscount`(20%)로 제한한 값입니다. 오차의 중위값은 다수가 서로 같으면 소수의 큰 차이를 보지 못해 퍼짐으로 보완합니다. 이상치를 뺐으면 하한은 `minDiscountWithOutliers`(10%)입니다. 단지가 4곳 미만이면 오차를 믿기 어려워 20%를 씁니다. 계산값이 20%를 넘으면 판별 근거에 `실제 위험은 더 큼`이라고 적고, 그 경우 신뢰도는 `하`입니다. 예전의 하위 25%는 단지 8곳이면 두 번째로 싼 단지 값이라 싼 단지 한두 곳에 끌려갔습니다. 이 방식은 공고 단지를 맞힐 때 예상되는 오차만큼 낮춰 잡습니다. 같은 단지 거래로 계산할 때는 그 거래들의 하위 25%를 그대로 씁니다. `마진율`은 안전 마진을 보수 시세로 나눈 비율입니다. 주택형은 기준을 넘는 것 중 마진이 가장 큰 것, 없으면 전체에서 마진이 가장 큰 것을 고르고 판별 근거에 적습니다.
9. **취득세(`acquisitionTax`)는 1주택 유상취득, 감면 없음을 가정합니다.** 6억 원 이하 1%, 9억 원 이상 3%, 그 사이는 직선으로 오르고 지방교육세로 세액의 10%를 더합니다. 분양가 기준이며 전용 85㎡ 초과의 농어촌특별세(0.2%)와 다주택 중과는 넣지 않았습니다. 실제 세액은 다를 수 있습니다.
10. `시세 신뢰도`는 표본 수, 단지 수, 보정값의 퍼짐, 단지끼리 서로를 맞혀 본 오차(`confidence`)로 정합니다. 연식 범위를 넓혔으면 내리거나 `하`로 둡니다(4번). `역 도보(분)`이 비어 있으면 `중`까지만 오릅니다. 입력은 있지만 비교 단지 값이 부족하면 한 단계 내립니다. 분양권 조회가 실패하면 한 단계 내립니다.

**판별 근거:** `역 도보 7분(입력)`처럼 입력 값을, 쓴 비교 단지를 모두 단지명과 보정 후 84㎡ 환산 금액(예: `광교중흥에스클래스 18.5억`), 역 거리 구간, 브랜드와 연식 보정으로 적고, 고른 범위(법정동 또는 시군구, 연식 범위)와 뺀 이상치 수, 보수 시세의 차감률을 적습니다. 단지명과 금액은 국토부 공개 자료입니다. Notion은 2000자에서 자릅니다. 카카오톡은 200자라 비교 단지 목록 없이 안전 마진, 마진율, 주택형, 신뢰도만 담은 짧은 근거를 보냅니다. 카카오톡이 실패해 메일로 대신 보낼 때는 전체 판별 근거를 함께 붙입니다. 단지명은 `S클래스`와 `에스클래스`처럼 영문과 한글 브랜드 표기를 같게 보고 묶습니다.

**호출 수와 시간:** `역 도보(분)`이 입력되고 같은 단지 거래로 값이 정해지지 않는 공고만 호출합니다. 시군구마다 목록 1회 이상(1,000건에 1회), 공고당 상세 정보 최대 `maxComparables × 주택형 수`회(면적이 겹치면 더 적습니다)이고, 같은 실행에서 같은 조회는 반복하지 않습니다. 실행당 `aptInfo.maxCallsPerRun`(300회)과 `budgetMs`(2분)에서 멈춥니다. 호출은 한 번에 10초까지 기다리고 시간 초과, 네트워크 오류, 5xx, 429는 한 번 다시 시도합니다. 미승인, 응답 형식 차이, 상한 도달을 포함한 모든 실패는 오류 메일 없이 `soft=`에 남고 그 실행의 호출을 멈춥니다. 데이터 없음(결과 코드 03, 항목 없음, 빈 목록)은 실패가 아니라 그 단지나 시군구의 값이 없는 것으로 보고 계속합니다. 판별 근거는 `역 정보 조회를 못 해`와 `비교 단지 역 정보 부족으로`를 구분합니다. 분양권 조회는 `presale.budgetMs`(2분)에서 멈춥니다.

**로그:** `collected` 줄의 `lotto_demoted`는 이전에 로또였다가 이번 계산에서 `아님` 또는 `대상 외`가 된 공고 수입니다. 알림과 메일에는 영향이 없습니다. `market` 줄에는 공동주택 호출 수, 역 보정 적용(`station_used`), 입력 없음(`station_no_input`), 비교 단지 값 부족(`station_no_data`), 이상치로 뺀 비교 단지 수(`complex_outliers`), 신뢰도별 건수, 메일을 보내지 않는 항목(`soft=`)이 남습니다. `apt_name_unmatched`는 공동주택 목록에서 찾지 못한 비교 단지 수입니다. `trade_tags`, `presale_tags`, `apt_tags` 줄은 값이 빠진 행의 수입니다. 첫 실행에서 `noFloor`, `noDate`, `noDealing`, `noJibun`, `noOwnership`이 `rows`와 같거나, `noField`, `badWalk`가 `details`와 같으면 태그명이나 값 형식이 다른 것이니 `src/sources/`의 해당 파일을 고치세요. `apt_tags`의 `bands=`는 `5~10분이내:3`처럼 읽은 구간 값별 건수이고, `listNoTotal`은 전체 건수 없이 온 목록 페이지 수입니다. `apt_tags`는 `역 도보(분)`이 입력된 공고가 있어야 값이 생깁니다. `sale_tag_names`, `presale_tag_names` 줄은 실거래 항목에서 본 태그 이름 목록입니다. 값은 남기지 않고 영문, 숫자, 밑줄로 된 이름만 최대 80개, 800자까지 남깁니다.
